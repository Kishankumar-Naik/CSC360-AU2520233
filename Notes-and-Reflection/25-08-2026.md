### Topic 1: `pom.xml` in Maven Projects

The `pom.xml` file is the main configuration file of a Maven project. POM stands for Project Object Model.

It contains important project information such as the `groupId`, `artifactId`, version, dependencies, plugins and Java compiler settings.

The `groupId` usually identifies the organisation or project namespace, while the `artifactId` identifies the application or library. Together with the version, these values identify the project when Maven builds or publishes it.

Dependencies are external libraries required by the project. Maven reads the dependency information from `pom.xml` and makes the required libraries available to the project.

A Maven project commonly follows a standard directory structure:

```text
src/main/java       application source code
src/main/resources  application resources
src/test/java       test source code
src/test/resources  test resources
target              generated build output
```

The `target` directory contains compiled classes and other generated files. Since Maven can create these files again, it is normally excluded from version control using `.gitignore`.

### Topic 2: Swing and JavaFX

JavaFX is a newer Java user interface toolkit, but Swing components can still be useful in some applications.

Swing provides components such as `JTable` and `JTree`, and these can be used with JavaFX through suitable integration. Understanding the relationship between Swing and JavaFX is useful when working with older Java applications while using newer GUI technologies.

### Topic 3: Threads and Processes

A process is an independent running program with its own memory space and system resources.

A thread is a smaller unit of execution inside a process. Threads within the same process share its memory, which makes communication easier, but it also means that shared data has to be handled carefully.

Some important differences are:

| Feature | Process | Thread |
|---|---|---|
| Memory | Separate memory space | Shares process memory |
| Communication | More expensive | Usually easier |
| Isolation | Stronger isolation | Less isolation |
| Creation cost | Generally higher | Generally lower |
| Failure impact | Usually limited to that process | Can affect the whole process |

A Java Swing application normally runs as one process containing several threads, including the Event Dispatch Thread and any worker threads created by the application.

### Topic 4: Swing Thread Safety and the Event Dispatch Thread

Swing is not thread-safe, so Swing components should normally be created or modified on the **Event Dispatch Thread (EDT)**.

The EDT handles user interface events and performs Swing updates. For example:

```java
SwingUtilities.invokeLater(() -> {
    JFrame frame = new JFrame("Example");
    frame.setVisible(true);
});
```

Painting is also performed by Swing on the EDT. The `Graphics` object passed to `paintComponent()` belongs to that particular painting operation and should be used inside the painting method rather than stored and reused by another thread.

A useful division of work is:

```text
EDT            creates components, handles events and paints
Worker thread  performs long-running calculations or I/O
Shared state   is updated using suitable thread-safe methods
```

### Topic 5: Preventing a Frozen GUI

If the EDT performs a long-running task, it cannot respond properly to user input, repaint requests or window events until the task finishes.

For example, a large loop, file operation, network request or complex calculation inside an event handler can make the GUI appear frozen.

The solution is to keep the EDT available for interface work and move long-running tasks to a background thread.

`SwingWorker` can be used for this:

```java
SwingWorker<String, Void> worker = new SwingWorker<>() {

    @Override
    protected String doInBackground() throws Exception {
        return performLongTask();
    }

    @Override
    protected void done() {
        resultLabel.setText(getResultSafely());
    }
};

worker.execute();
```

Here, the long-running operation is performed in the background, while the final UI update is handled safely after the work is completed.

### Topic 6: JavaFX "Click Me" Button Program

We also looked at a basic JavaFX button example.

A JavaFX `Button` can be connected to an `EventHandler`, which runs when the user presses the button. The event can then be used to update the user interface, such as changing a label.

This example helped show the basic idea of event-driven programming in JavaFX and the importance of performing UI updates on the JavaFX Application Thread.
